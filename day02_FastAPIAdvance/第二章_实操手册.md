## 1. 公共骨架（后面反复复用，先敲熟）

### 骨架 A —— 第 11 课用（只建表）

```python
from datetime import datetime

from fastapi import FastAPI
from sqlalchemy import DateTime, func, String, Float
from sqlalchemy.ext.asyncio import create_async_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

app = FastAPI()

# 1. 创建异步引擎
ASYNC_DATABASE_URL = "mysql+aiomysql://root:root@localhost:3306/fastapi_demo?charset=utf8mb4"
async_engine = create_async_engine(
    ASYNC_DATABASE_URL,
    echo=True,          # 输出 SQL 日志，学习期开着，能看清 ORM 生成了什么 SQL
    pool_size=10,       # 连接池活跃连接数
    max_overflow=20     # 允许额外溢出的连接数
)


# 2. 定义模型类：基类（公共字段）+ 表模型类
class Base(DeclarativeBase):
    create_time: Mapped[datetime] = mapped_column(
        DateTime, insert_default=func.now(), default=func.now(), comment="创建时间")
    update_time: Mapped[datetime] = mapped_column(
        DateTime, insert_default=func.now(), default=func.now(),
        onupdate=func.now(), comment="修改时间")


class Book(Base):
    __tablename__ = "book"

    id: Mapped[int] = mapped_column(primary_key=True, comment="书籍id")
    bookname: Mapped[str] = mapped_column(String(255), comment="书名")
    author: Mapped[str] = mapped_column(String(255), comment="作者")
    price: Mapped[float] = mapped_column(Float, comment="价格")
    publisher: Mapped[str] = mapped_column(String(255), comment="出版社")


# 3. 建表：应用启动时调用
async def create_tables():
    async with async_engine.begin() as conn:      # 开启事务
        await conn.run_sync(Base.metadata.create_all)   # 同步建表 API 异步化执行


@app.on_event("startup")
async def startup_event():
    await create_tables()


@app.get("/")
async def root():
    return {"message": "Hello World"}


if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="127.0.0.1", port=8000)
```

**要点讲解**

| 知识点 | 说明 |
|---|---|
| `DeclarativeBase` | SQLAlchemy 2.0 的新式基类。`Base` 里只写公共字段（创建/更新时间），`Book` 继承后自动带上 |
| `Mapped[int]` / `mapped_column` | 2.0 的类型注解式写法，`Mapped[str]` 会推导出 `NOT NULL`；`-> Mapped[Optional[str]]` 才是可空 |
| `insert_default` vs `default` | `default` 是**插入时**由 ORM 端填值；`insert_default` 让 DDL 带上默认值。两者都写是课件的写法 |
| `onupdate=func.now()` | 任何 UPDATE 时自动刷新更新时间 |
| `create_all` | **幂等**：表存在就跳过，不会报错也不会改表结构 |

> `@app.on_event("startup")` 在新版 FastAPI 里已**弃用**，启动时会打印 DeprecationWarning，
> **属于正常现象**，不影响运行（新版写法是 `lifespan`，第二章暂不展开）。

**验证**：运行后去 `/docs` 能看到 `/` 接口；控制台 `echo=True` 会打印建表相关 SQL；
数据库里 `book` 表已存在（我已为你建好，`create_all` 会直接跳过）。

### 骨架 B —— 第 12~20 课用（在骨架 A 基础上再加会话与依赖项）

把骨架 A 的 `from fastapi import FastAPI` 改为 `from fastapi import FastAPI, Depends`，
`from sqlalchemy import ...` 末尾加上 `select`，然后在 `@app.get("/")` 之前插入这段：

```python
AsyncSessionLocal = async_sessionmaker(
    bind=async_engine,          # 绑定引擎
    class_=AsyncSession,        # 指定会话类
    expire_on_commit=False      # 提交后对象不过期，避免再查一次库
)


async def get_database():
    async with AsyncSessionLocal() as session:
        try:
            yield session               # 把会话交给路由函数
            await session.commit()      # 正常走完 → 提交
        except Exception:
            await session.rollback()    # 出异常 → 回滚
            raise
        finally:
            await session.close()       # 收尾关闭
```

对应的 import 补上：

```python
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession
```

**要点讲解**

- `yield` 让这个函数变成**带清理逻辑的依赖项**：FastAPI 在路由返回后回来执行 `yield` 之后的代码。
- **提交时机很关键**：`commit()` 放在 `yield` 之后，所以第 18/19/20 课的路由里**还要再 `await db.commit()` 一次**吗？
  课件里确实这么写了——那是为了「确保在返回响应前已落库」，属于双保险；真正的兜底提交在后面。
- `expire_on_commit=False`：默认 `True` 时，commit 后对象属性会过期，序列化响应时会触发额外 SELECT；设 False 可避免。

## 2. 第 09 课 · 中间件

**文件**：`09_middleware.py`

```python
from fastapi import FastAPI

app = FastAPI()


@app.middleware("http")
async def middleware2(request, call_next):
    print("中间件2 start")
    response = await call_next(request)
    print("中间件2 end")
    return response


@app.middleware("http")
async def middleware1(request, call_next):
    print("中间件1 start")
    response = await call_next(request)
    print("中间件1 end")
    return response


@app.get("/")
async def root():
    return {"message": "Hello World"}


if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="127.0.0.1", port=8000)
```

**讲解**

- 中间件是「请求进 → 处理 → 响应出」的**洋葱模型**：`start` 顺序执行，`end` 逆序执行。
- ⚠️ **注意：课件对这个顺序的说法是错的，以实测为准。**
  在你这套环境（FastAPI 0.141.1 / Starlette 1.6.0）实测，这段代码的真实打印顺序是：

  ```
  中间件1 start
  中间件2 start
  中间件2 end
  中间件1 end
  ```

  也就是 **后注册的 `middleware1` 在最外层、最先执行**。
  原因：Starlette 的 `add_middleware()` 是依次 `insert(0, …)` 的，最后注册的会被插到
  `app.user_middleware` 列表的**最前面**，而 **index 0 就是最外层**。
  课件里「中间件2 先 start」是更老版本 Starlette 的行为，别跟着背。

  **验证方法**：`print([m.kwargs["dispatch"].__name__ for m in app.user_middleware])`，
  列表第 0 个就是最外层。想不起来顺序时用这行代码确认，比记结论靠谱。
- `call_next(request)` 就是把请求往下一层传；不调用它，请求就到不了路由。

## 3. 第 10 课 · 依赖注入

**文件**：`10_dependency.py`

```python
from fastapi import FastAPI, Query, Depends

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello World"}


# 1. 依赖项：把分页参数逻辑抽出来共用
async def common_parameters(
    skip: int = Query(0, ge=0),
    limit: int = Query(10, le=60)
):
    return {"skip": skip, "limit": limit}


# 2. 声明依赖项 → 依赖注入
@app.get("/news/news_list")
async def get_news_list(commons=Depends(common_parameters)):
    return commons


@app.get("/user/user_list")
async def get_user_list(commons=Depends(common_parameters)):
    return commons


if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="127.0.0.1", port=8000)
```

**讲解**

- `Depends(common_parameters)`：FastAPI 会**自动解析** `common_parameters` 的形参（它自己也是个带 `Query` 校验的函数），
  先执行它，再把返回值注入 `commons`。这就是「依赖注入」。
- 价值：**分页参数的校验规则写一次，新闻/用户两个接口共用**。后面第 12 课的 `get_database` 用的是同一个机制。

**验证**（浏览器 / `/docs`）

| 请求 | 结果 |
|---|---|
| `/news/news_list` | `{"skip":0,"limit":10}` |
| `/news/news_list?skip=5&limit=3` | `{"skip":5,"limit":3}` |
| `/user/user_list?skip=-1` | 422 校验错误（`ge=0` 生效） |
| `/user/user_list?limit=61` | 422 校验错误（`le=60` 生效） |

## 5. 第 12 课 · 路由中使用 ORM

**文件**：`12_orm_in_router.py` —— **骨架 B**，末尾加：

```python
@app.get("/book/books")
async def get_book_list(db: AsyncSession = Depends(get_database)):
    # 查询全部图书
    result = await db.execute(select(Book))
    book = result.scalars().all()
    return book
```

**讲解**

- 依赖注入在这里的作用：**每个请求拿到一个独立的数据库会话**，请求结束自动 commit/close——
  这是 FastAPI + SQLAlchemy 异步的标准姿势。
- `select(Book)` 是 SQLAlchemy 2.0 的查询构造器（替代 1.x 的 `session.query`）。
- `result.scalars().all()`：`execute` 返回的是 **Row 结果集**，`.scalars()` 取出第一列实体对象，`.all()` 变列表。

**验证**：`/book/books` → 返回 8 本书的 JSON（含中文字段）。

> 小坑：如果直接返回 ORM 对象报序列化错误，说明你用的是旧版 SQLAlchemy 或忘了 `.scalars()`。

## 7. 第 14 课 · 查询条件

**文件**：`14_query_condition.py` —— **骨架 B**，末尾加：

```python
@app.get("/book/get_book/{book_id}")
async def get_book_list(book_id: int, db: AsyncSession = Depends(get_database)):
    result = await db.execute(select(Book).where(Book.id == book_id))
    book = result.scalar_one_or_none()
    return book


@app.get("/book/search_book")
async def get_search_book(db: AsyncSession = Depends(get_database)):
    result = await db.execute(select(Book).where(Book.price >= 200))
    books = result.scalars().all()
    return books
```

**讲解**

- `.where(条件)` 就是 SQL 的 `WHERE`。多个条件用 `.where(a).where(b)` 或 `.where(a, b)` 叠加（AND）。
- 三个「取单条」的区别，这是本课最容易混的点：

  | 方法 | 命中 0 条 | 命中 1 条 | 命中多条 |
  |---|---|---|---|
  | `scalar_one_or_none()` | `None` | 对象 | **抛异常** |
  | `scalar_one()` | **抛异常** | 对象 | **抛异常** |
  | `scalars().first()` | `None` | 对象 | 第一条 |

  按主键查用 `scalar_one_or_none()` 最严谨：既能容忍查不到，又能暴露「居然查出多条」的异常。

- 比较运算直接写 Python 运算符（`==`、`>=`、`<`），SQLAlchemy 会翻译成 SQL。

**验证**

| 请求 | 返回 |
|---|---|
| `/book/get_book/3` | 《FastAPI Web开发》 |
| `/book/get_book/999` | `null` |
| `/book/search_book` | **`[]`** —— 因为我们库里最贵 139，`>= 200` 没人 |

> ✍️ **动手改一下**：把 `200` 改成 `100`，就能查到 id=2（139）和 id=5（128）两本。

## 8. 第 15 课 · 模糊 / 与非 / 包含

**文件**：`15_query_like_and_or_in.py` —— **骨架 B**，末尾加：

```python
@app.get("/book/search_book")
async def get_search_book(db: AsyncSession = Depends(get_database)):
    # ① 模糊查询：like()   % 代表任意个字符，_ 代表一个字符
    # result = await db.execute(select(Book).where(Book.author.like("曹_")))
    # result = await db.execute(select(Book).where(Book.author.like("曹%")))

    # ② 与非：&（且）、|（或）、~（非）—— 注意每个条件要加括号！
    # result = await db.execute(
    #     select(Book).where((Book.author.like("曹%")) | (Book.price > 100)))

    # ③ 包含：in_()
    id_list = [1, 3, 5, 7]
    result = await db.execute(select(Book).where(Book.id.in_(id_list)))
    book = result.scalars().all()
    return book
```

**讲解**

- `like` 里的 `%` / `_` 和 SQL 一致；`ilike` 在 MySQL 里不区分大小写（MySQL 的 `like` 本身就不区分）。
- `&` `|` `~` 来自 Python 运算符重载，**优先级比比较运算符高**，所以
  `Book.author.like("曹%") | Book.price > 100` 是错的，必须写成
  `(Book.author.like("曹%")) | (Book.price > 100)`。**忘加括号是本课最高频的错**。
- `in_` 后面带下划线，避免和 Python 关键字 `in` 冲突。

> ⚠️ **和课件数据的差异**：课件里 `曹%` / `曹_` 的示例是针对课件原始数据的，
> 我们这套演示数据里**没有作者姓曹**，直接跑那两个注释会得到 `[]`。
> 请用我们库里的真实数据来演示：
> - `Book.author.like("Python%")` → id 1、7（Python编程从入门到实践、Python异步编程）
> - `Book.author.like("C%")` → id 7（Caleb Hattingh）
> - `(Book.author.like("Python%")) | (Book.price > 100)` → id 1、2、5、7

**验证**：默认代码（`in_([1,3,5,7])`）→ 返回 id 为 1、3、5、7 的 4 本书。

## 9. 第 16 课 · 聚合查询

**文件**：`16_aggregate.py` —— **骨架 B**，末尾加：

```python
@app.get("/book/count")
async def get_count(db: AsyncSession = Depends(get_database)):
    # select( func.聚合函数(模型类.属性) )
    # result = await db.execute(select(func.count(Book.id)))
    # result = await db.execute(select(func.max(Book.price)))
    # result = await db.execute(select(func.sum(Book.price)))
    result = await db.execute(select(func.avg(Book.price)))
    num = result.scalar()   # 提取单个标量值
    return num
```

**讲解**

- 写法模板：`select(func.函数名(模型类.属性))`。
- 取值用 **`result.scalar()`**（单个值），不是 `.scalars()`（实体列表）—— 这是本课要点。
- `func.*` 覆盖 `count / max / min / sum / avg`，对应 SQL 聚合函数。

**验证**（基于 8 条演示数据，价格 89/139/99/79/128/45/69/59）

| 改成 | 返回值 |
|---|---|
| `func.count(Book.id)` | `8` |
| `func.max(Book.price)` | `139.0` |
| `func.min(Book.price)` | `45.0` |
| `func.sum(Book.price)` | `707.0` |
| `func.avg(Book.price)` | `88.375` |

> 返回的是裸数字（如 `88.375`），不是 JSON 对象。想包一层可写 `return {"avg": num}`。

## 10. 第 17 课 · 分页查询

**文件**：`17_pagination.py` —— **骨架 B**，末尾加：

```python
@app.get("/book/get_book_list")
async def get_book_list(
    page: int = 1,
    page_size: int = 3,
    db: AsyncSession = Depends(get_database)
):
    # （页码 - 1） * 每页数量
    skip = (page - 1) * page_size

    # offset 跳过多少条  ； limit 取多少条
    stmt = select(Book).offset(skip).limit(page_size)
    result = await db.execute(stmt)
    books = result.scalars().all()
    return books
```

**讲解**

- 分页公式：`offset = (page - 1) * page_size`，**页码从 1 开始**。
- `page` / `page_size` 是普通查询参数（没有 `Query()` 包装时 FastAPI 从查询串自动取值）。
- 生产环境建议补上边界校验，例如 `page: int = Query(1, ge=1)`、`page_size: int = Query(3, ge=1, le=100)`，
  否则 `page=0` 会得到负数 offset。

**验证**（共 8 条）

| 请求 | 返回 id |
|---|---|
| `/book/get_book_list` | 1、2、3（默认第 1 页，每页 3 条） |
| `/book/get_book_list?page=2` | 4、5、6 |
| `/book/get_book_list?page=3` | 7、8 |
| `/book/get_book_list?page=4` | `[]`（越界返回空列表） |

## 11. 第 18 课 · 新增数据

**文件**：`18_insert.py` —— **骨架 B**，import 补 `from pydantic import BaseModel`，末尾加：

```python
# 用户输入 → 请求体模型
class BookBase(BaseModel):
    id: int
    bookname: str
    author: str
    price: float
    publisher: str


@app.post("/book/add_book")
async def add_book(book: BookBase, db: AsyncSession = Depends(get_database)):
    # dict → ORM 对象 → add → commit
    book_obj = Book(**book.__dict__)
    db.add(book_obj)
    await db.commit()
    return book
```

**讲解**

- `BookBase(BaseModel)` 定义**请求体**结构：FastAPI 自动做类型校验并生成 `/docs` 表单。
- `Book(**book.__dict__)` 把 Pydantic 对象转成 ORM 对象（本质是字典解包）。
  更规范的写法是 `Book(**book.model_dump())`（Pydantic v2 已弃用 `__dict__` 直取）。
- `db.add()` 只是把对象放进**会话的待提交区**，真正落库靠 `await db.commit()`。

**验证**：`/docs` → `POST /book/add_book` → `Try it out` → 填：

```json
{"id": 9, "bookname": "Effective Python", "author": "Brett Slatkin", "price": 79.5, "publisher": "机械工业出版社"}
```

→ 返回同样内容。之后访问 `/book/books`（第 12 课）或第 16 课的 `/book/count`，会看到总数变成 **9**。

> 注意：表主键是 `AUTO_INCREMENT`，但这里**显式传了 id**，所以 id 必须自己保证不重复；
> 重复提交同一个 id 会报 `IntegrityError`（主键冲突）。想演示自增可以去掉 `id` 字段。

## 12. 第 19 课 · 更新数据

**文件**：`19_update.py` —— **骨架 B**，import 改为
`from fastapi import FastAPI, Depends, HTTPException`，加 `from pydantic import BaseModel`，末尾加：

```python
class BookUpdate(BaseModel):
    bookname: str
    author: str
    price: float
    publisher: str


@app.put("/book/update_book/{book_id}")
async def update_book(book_id: int, data: BookUpdate, db: AsyncSession = Depends(get_database)):
    # 1. 先查
    db_book = await db.get(Book, book_id)

    if db_book is None:
        raise HTTPException(status_code=404, detail="查无此书")

    # 2. 再改（重新赋值即可，ORM 会跟踪属性变化）
    db_book.bookname = data.bookname
    db_book.author = data.author
    db_book.price = data.price
    db_book.publisher = data.publisher

    # 3. 提交
    await db.commit()
    return db_book
```

**讲解**

- 设计思路：**路径参数传 id**（定位哪一条），**请求体传新数据**（改成什么）。所以 `BookUpdate` 里**不含 id**。
- ORM 的「**工作单元**」模式：改对象属性不用写 UPDATE，`commit()` 时会自动比对并生成 UPDATE 语句。
  这正是 `echo=True` 日志里能看到的效果。
- `HTTPException(404)` 用于「查不到」；FastAPI 会直接返回 404 + `{"detail": "查无此书"}`。

**验证**

1. 先 `PUT /book/update_book/1`，body：
   ```json
   {"bookname": "Python编程从入门到实践(第3版)", "author": "Eric Matthes", "price": 99.0, "publisher": "人民邮电出版社"}
   ```
   → 返回更新后的对象。
2. `PUT /book/update_book/999` → **404** `{"detail":"查无此书"}`。
3. 去数据库 `SELECT * FROM book WHERE id=1;` → `update_time` 已被 `onupdate` 自动刷新。

## 13. 第 20 课 · 删除数据

**文件**：`20_delete.py` —— **骨架 B**，import 改为
`from fastapi import FastAPI, Depends, HTTPException`，末尾加：

```python
@app.delete("/book/delete_book/{book_id}")
async def delete_book(book_id: int, db: AsyncSession = Depends(get_database)):
    # 先查再删，最后提交
    db_book = await db.get(Book, book_id)

    if db_book is None:
        raise HTTPException(status_code=404, detail="查无此书")

    await db.delete(db_book)
    await db.commit()
    return {"msg": "删除图书成功"}
```

**讲解**

- 和更新一样是「**先查再操作**」：`db.get` 拿到持久化对象，`db.delete` 标记删除，`commit` 落库。
- 也可以不查，直接构造 `Book(id=xxx)` 走 `delete` 语句，但**先查再删**能区分「真删了」和「本来就没有」，
  所以课件用这种方式，返回 404 语义更准确。

**验证**

| 请求 | 结果 |
|---|---|
| `DELETE /book/delete_book/8` | `{"msg":"删除图书成功"}` |
| 再删一次 8 | 404 `{"detail":"查无此书"}` |

## 14. 常见报错速查

| 报错 | 原因 / 解决 |
|---|---|
| `ModuleNotFoundError: No module named 'aiomysql'` | 依赖没装或装的不是项目 venv：PyCharm `Settings → Project → Python Interpreter` 确认解释器，再 Terminal 里 `pip install ...` |
| `Access denied for user 'root'@'localhost'` | 连接串密码不对。本项目是 `root:root`，库名 `fastapi_demo` |
| `Unknown database 'fastapi_demo'` | 库没建。跑一次 `init_db.sql` |
| `[Errno 10048] error while attempting to bind on address` | 8000 端口被上一个服务占用。**点红色方块停掉上一个**，或换端口 `port=8001` |
| `RuntimeError: You must pass the application as an import string to enable 'reload'` | 用了 `uvicorn.run(app, reload=True)`。改成字符串形式 `uvicorn.run("09-中间件:app", reload=True)`，或直接去掉 `reload` |
| `DeprecationWarning: on_event is deprecated` | 正常，可忽略 |
| `sqlalchemy.exc.MultipleResultsFound` | 用了 `scalar_one_or_none()` 但条件命中了多条 |
| `sqlalchemy.exc.IntegrityError: Duplicate entry` | 第 18 课重复提交同一个 id |
| 返回的中文是 `????` | 连接串没带 `charset=utf8mb4`（或库/表不是 utf8mb4）。本项目的库和表都已是 utf8mb4 |
